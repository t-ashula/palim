# ADR-0038: WPT 進捗レポートの集計方針

## ステータス

accepted

## コンテキスト

ADR-0033 で wptrunner との接続と実行結果の保存を決定したが、WPT の進捗を継続的に比較するための母数、集計単位、保存先は定めていない。

実行結果だけを集計すると、未実行の test URL が母数に含まれず、実装範囲全体に対する進捗を判断できない。
WPT には test document の URL と、その document 内で `test()` などにより報告される subtest という異なる単位があり、両者を同じ件数として扱うこともできない。

また、WPT の実行結果を他の conformance test と同じレポートとして扱うと、異なる集計単位の結果が互いに上書きされる。
個別の test URL を調査する実行によって、対象領域全体の進捗レポートが置き換わることも避ける必要がある。

## 決定

- WPT の継続的な進捗レポートは、他の conformance test のレポートから分離する
- 機械可読な集計結果と、同じ内容から決定的に生成する人間向け表示を提供する
- 進捗の母数は、固定した WPT revision の対象領域と対象外領域の設定で選択した集合とする
- レポートには WPT revision と対象範囲を記録する
- URL 単位の状態は `pass`、`fail`、`error`、`timeout`、`skip`、`pending` とする
- 選択対象であり、今回の実行結果に存在しない URL を `pending` とする
- `pending` 以外の URL 数を実行済み数とし、実行済み数を母数で割った値を進捗率とする
- `pass` の URL 数を実行済み数で割った値を成功率とする
- 対象領域ごとに、対象数、実行済み数、各状態の件数、進捗率、成功率を集計する
- subtest は実行された test document 内で報告された件数だけを、URL 集計とは別の表に集計する
- subtest の件数をURL進捗の母数には使用しない
- 対象範囲全体の実行だけが、継続的な進捗レポートを更新する
- 個別 test の調査および対象範囲外を含む実行は、継続的な進捗レポートを更新しない
- 個々の実行結果は、継続的な進捗レポートとは分離して保持する

## 影響

- 未実行 URL が `pending` として現れ、実行済み test だけを見た成功率と、対象範囲全体の進捗率を区別できる
- WPT revision または対象範囲の変更時には母数が変化し、その変更をレポート差分として確認できる
- URL の成功数と subtest の成功数を混同せずに比較できる
- 個別 test の調査は継続的な進捗レポートへ影響しない
- WPT と他の conformance test のレポートを独立して保持できる
- 継続的な進捗レポートの更新には、対象範囲全体を実行する必要がある

## 代替案

### 実行結果に含まれる URL だけを母数とする

未実行 URL を表現できず、実装範囲全体の進捗率にならないため採用しない。

### subtest を進捗の母数とする

未実行 document の subtest 数は実行前に確定できず、manifest から固定した母数を得られないため採用しない。

### WPT レポートを他の conformance test と共有する

異なる test suite のレポートが互いに上書きされ、集計単位も曖昧になるため採用しない。

### 個別実行でも継続的な進捗レポートを更新する

一部の URL だけを実行した結果から全体の最新状態を判断できなくなるため採用しない。
